# 月费率摊成年化（installment-apr）

结账页写着「**12 期，月费率 0.75%**」——把这句话摊开成一张逐期票据：每期还的钱里本金和手续费各多少、
手续费一共多少、**折算成年化到底是多少**、**提前还清是省还是亏**，以及「免息」在什么条件下其实也不便宜。

- 页面：`index.html`（单文件，离线可用，不联网、不内置任何费率表）
- 引擎：`core.js`（纯函数，浏览器与 node 通用；`window.AppCore`）
- 界面：`ui.js` + `template.html`，`node build.cjs` 合成 `index.html`
- 测试：`node --test tests/core.test.cjs`
- 浏览器验收：`node 验收脚本.cjs --tag 本地`（或 `--tag 线上 --url <线上地址>`）
- 截图：`node 截图.cjs 本地`（整页截图 + Pillow 裁剪区块图）
- 封面：`node make-cover.cjs`（1200×1200）

## 模型（全部写在页面上）

1. **手续费总额** `F = 本金 P × 月费率 f × 期数 n`。**手续费是按整笔本金每期收的**，不是按剩下没还的部分 ——
   这是「年化 = 月费率 × 12」这个直觉出错的地方。
2. **三种还款口径**（同一笔手续费，付款时点/形状不同）：
   - `每期还款额恒定`：`A = (P + F) / n`，其中本金部分 `A − P·f` 逐期恒定；
   - `每期本金相同 + 每期收手续费`：每期 `P/n + P·f`（每期还款额也恒定，是同一类现金流）；
   - `手续费首期付清`：第 1 期 `P/n + F`，第 2…n 期只还 `P/n`。
3. **实际月利率 i** 是 `Σ_{t=1..n} pay_t / (1+i)^t = P` 的解（先把每期还款按本金归一化，再在确认变号的区间里二分）。
4. **实际年化（复利口径）= (1+i)^12 − 1**；对照用的 **比例直算 = f × 12**。
5. **提前还清**：第 k 期账单日付「第 k 期手续费 + 本期还款前的剩余本金 + 违约金（剩余本金 × v）」，之后不再还款；
   `v*` 是让「提前还清的实际年化 = 不还清的实际年化」的违约金率。**总支出**与**折算年化**是两个不同的口径，页面分开写。
6. **免息也不便宜**：标价差 `gap = 分期标价 − 一次性付清价` 与原样本金在分期期间能赚到的钱对比；
   临界现金收益率 `r* = (1 + gap/P)^(12/n) − 1`（超过输入上限时如实写「超过可输入上限」，不硬给一个填不进去的数）。
7. **显示**：金额两位小数、百分比两位小数，全部由同一次 `compute` 的输出渲染。

## 不做的事

不推荐任何分期产品、不比较任何平台、不给「该不该分期」的消费建议、不判断任何产品合法与否；
不联网、不查任何银行或平台、不内置任何费率表、不声称任何地区的费率现状；
不含服务费/保险费/会员费/平台佣金等第三方费用、逾期罚息与征信影响、额度占用的机会成本、
商家把手续费加进标价而你看不到的部分（只能按标价差反解）、浮动费率与中途改期、跨币种与汇率、税务处理。
默认场景与 8 个内置场景全部是**虚构示例**，不代表任何真实产品、银行或平台的费率。

## 已知的量级边界

~~本金 1000 万级别时年化会偏 3%~~ —— 这是开发中抓到的真缺陷（`npv` 闭包内层循环变量与外层二分同名，
内层把外层计数器改掉，二分只走一步就退出）。已修：先按本金归一化再二分，并加了回归测试
（`M0`：0.01 元到 1000 万元的结果必须逐位一致；`M0b`：根处归一化 NPV ≤ 1e-12 且不落在探测点上）。
